# 验收对照表（第二轮评审清单 → 实现位置 → 测试）

> 说明：第一轮整改完成后未提交推送，导致评审在远端 main（48622c6）上看到的仍是旧代码。
> 本轮已全部提交。下表逐条对应评审的 7 项发现。

## 1. P0：video_query / image_query 字段不一致 ✅

- `src/script.py`：大纲提示词要求 `video_query`；`normalize_outline()` 把模型任何别名
  （`image_query/query/search_query/...`）统一成内部唯一字段 `video_query`；
  `validate()` 把"缺 video_query"定为 hard 错误，触发修复重试，仍缺失抛 `ScriptError`。
- `autopost.py`：素材阶段只读 `sec["video_query"]`，无任何 `image_query` 引用。
- 测试：`tests/test_script.py::test_normalize_maps_image_query_alias`、
  `test_validate_missing_query_is_hard`、`test_generate_fixes_broken_outline`、
  `test_generate_gives_up_after_fix_attempts`（固定模拟大纲，不调用真实 API）。

## 2. P1：选题状态机（done 导致重复生成）✅

- `src/store.py`：状态机 `pending → generating → review → ready → published`（+failed）。
  制作完成（手动上传模式）标记 `ready` 而非 `done/published`；
  `is_topic_done()` 认可 ready+published；失败记阶段/原因/重试次数，超限后需显式 `redo`；
  `claim_topic()` 单条 UPDATE 原子领取；旧库（dryrun/done/failed:x）增量迁移不丢数据。
- 测试：`tests/test_store.py`（原子领取、重试上限、迁移、review 阻塞、崩溃恢复）；
  `tests/test_pipeline_e2e.py::test_full_pipeline_and_idempotence`（二次运行不重复生产）。

## 3. P1：启动前检查 ✅

- `src/precheck.py`：在消耗任何 API 额度之前检查——API Key 存在性（占位符=未配，
  绝不打印密钥值）、YAML 字段与类型、BGM 目录存在且含 MP3、目录可写、ffmpeg 可用、
  Pexels 认证/智谱连通性（区分网络失败与认证失败）。
- `config.yaml` 的 `bgm_dir` 为显式配置项，缺失/为空直接报错（仍默认指向共享曲库路径，
  但失败发生在启动时、且语义是"显式配置的共享路径"而非隐式依赖仓库结构）。
- 已实测：无 Key 首跑输出清晰错误清单并以退出码 1 结束，零 API 消耗。
- 测试：`tests/test_precheck.py`（密钥缺失/占位符、配置非法、BGM 空目录/缺目录）。

## 4. P1：取消不相关素材的静默兜底 ✅

- `src/material.py::search_footage()`：确定性改写阶梯
  （原词 → 去尾词放宽 → 主题词+核心词 → china+核心词 → 通用兜底）；
  兜底命中强制 `fallback=True` 打标并写日志警告；阶梯全部落空则任务失败进入待处理，
  **不会**拿城市风景冒充熊猫/兵马俑段落；网络/认证错误直接上抛（换词无意义）。
- `used_ids` 防同集重复 + `data/recent_assets.json` 跨集避让，均保留。
- 测试：`tests/test_material.py::test_search_footage_walks_ladder`、
  `test_search_footage_fallback_is_flagged`、`test_search_footage_exhausted_returns_none`。

## 5. P2：素材来源元数据 ✅

- 每段素材记录（`materials/index.json` + manifest）：Pexels 视频 ID、来源页 URL、
  **作者**（本轮新增，取自 API `user.name`）、下载直链、license、
  实际使用的**片段区间**（segment_start/segment_seconds/loop_fill，本轮新增）、
  改写阶梯层级、对应旁白段落号。
- `upload_info.txt` 的署名行格式：`Pexels #<id> by <author>: '<query>' , used X-Ys (<url>) — <license>`。
- 测试：`tests/test_pipeline_e2e.py`（断言 index 与 upload_info 含作者与片段区间）、
  `tests/test_material.py::test_pick_filters_portrait_and_used`（作者字段）。
